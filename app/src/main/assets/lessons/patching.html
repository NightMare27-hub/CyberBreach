Software patching

Software vendors regularly publish security patches that fix known vulnerabilities (identified by CVE numbers). Attackers scan the internet for systems still running unpatched versions and exploit them automatically.

Why blocking IPs is not enough

Blocking a single attacker’s IP address stops that one person, but the vulnerability remains. Another attacker from a different address can exploit the same flaw minutes later. Only applying the patch closes the hole for good.

Best practices

  • Keep an inventory of all software and their versions
  • Subscribe to vendor security advisories and CVE feeds
  • Apply critical patches within 24–72 hours of release
  • Test patches in a staging environment before rolling out to production
  • Use automated patch management tools where possible
